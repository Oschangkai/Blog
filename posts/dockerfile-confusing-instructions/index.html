Dockerfile 常搞混的指令

COPY 與 ADD

兩者都能把檔案複製進 image，ADD 多了幾個功能：

  • 來源是本機的 tar 壓縮檔（gzip、bzip2、xz）時，會自動解壓縮到目的地
  • 來源可以是遠端 URL，可搭配 --checksum 驗證，但不會自動解壓縮
  • 來源可以是 Git repository
COPY package.json /app/
ADD app.tar.gz /app/                    # 自動解壓縮至 /app/
ADD https://example.com/a.tar.gz /tmp/  # 只下載，不解壓縮

官方建議沒有用到上述功能時一律用 COPY，行為比較好預期。

EXPOSE 的用法

EXPOSE 用來說明容器會監聽哪些 port，預設是 TCP，也可以指定 UDP：

EXPOSE 8080
EXPOSE 53/udp

它只是寫進 image 的 metadata，與 host 能不能連得到容器無關。實際用途有兩個：

  • 當作文件，讓使用 image 的人知道要對應哪個 port，docker image inspect 看得到
  • 搭配 docker run -P，把所有 EXPOSE 的 port 對應到 host 的隨機 port

image 不需要事先 EXPOSE 就能使用 docker run -p <host_port>:<container_port> 對應 container port 到 host。同一個 user-defined network 裡的容器，不論有沒有 EXPOSE，都能互相連到對方的任何 port。

CMD 與 ENTRYPOINT

  • ENTRYPOINT：容器啟動時固定執行的程式，要用 docker run --entrypoint 才能覆蓋
  • CMD：預設指令或預設參數，docker run <image> 後面接的參數會整個取代它

兩者同時存在時，CMD 會變成 ENTRYPOINT 的預設參數：

ENTRYPOINT ["ping"]
CMD ["localhost"]

docker run my-ping            # ping localhost
docker run my-ping google.com # ping google.com

exec form 與 shell form 

ENTRYPOINT ["ping", "localhost"]  # exec form
ENTRYPOINT ping localhost         # shell form，等同 /bin/sh -c "ping localhost"

建議用 exec form。shell form 的 ENTRYPOINT 有兩個問題：

  • PID 1 是 /bin/sh，docker stop 送出的 SIGTERM 不會轉給你的程式，最後要等逾時被 SIGKILL
  • CMD 和 docker run 後面的參數都會被忽略

組合結果

參考官方文件：

沒有 ENTRYPOINTENTRYPOINT exec_entry p1ENTRYPOINT ["exec_entry", "p1"]
沒有 CMD錯誤，不允許/bin/sh -c exec_entry p1exec_entry p1
CMD ["exec_cmd", "p1"]exec_cmd p1/bin/sh -c exec_entry p1exec_entry p1 exec_cmd p1
CMD exec_cmd p1/bin/sh -c exec_cmd p1/bin/sh -c exec_entry p1exec_entry p1 /bin/sh -c exec_cmd p1

其他要注意的地方：

  • 多個 CMD 或 ENTRYPOINT 只有最後一個有效
  • 在子 image 設定 ENTRYPOINT 會把 base image 的 CMD 清空，需要的話要重新設定 CMD
